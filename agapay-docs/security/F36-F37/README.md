# F36–F37: uncertainty safeguards and reproducible feature profiles

F36's engineering controls are implemented. **There is no newly trained field model, measured flood-warning accuracy or validated operational uncertainty claim.** The supplied policy is provisional and cannot authorize release. F37 now separates dependency profiles, replaces private integration artifacts with generated synthetic fixtures, checks contracts across clients, runs web/browser tests, audits dependencies and builds the core container in CI. [RESULTS.md](RESULTS.md) distinguishes observed local results from hosted/Linux/container and field acceptance.

## Field decision evaluation

`app/ml/decision_evaluation.py` reports 30/60/90-minute errors, individual events, event peak errors and their distributions, station, calendar month/reviewed season, peak local-depth band, reviewed storm intensity and missingness. A depth band is **not** a rainfall-intensity measurement. Unprovided storm intensity is labeled unvalidated. Each model remains bound to one station/datum/configuration; results are not pooled across sites as a transfer claim.

Calibration events are separate from training and later test events. Their target windows must not overlap events in the same split. A 90-minute purge separates calibration labels from test origins. The interval radius is the finite-sample order statistic of calibration-event maximum absolute errors across every origin and horizon, floored at the reviewed measurement uncertainty. This deliberately treats an event, rather than neighboring sensor rows, as the uncertainty unit. Later withheld events measure joint all-horizon coverage, availability, per-horizon coverage and peak errors. Whole-event paired bootstrapping estimates candidate-versus-persistence/rate MAE gain with deterministic 95% percentile intervals. It does not establish independence merely by assigning different IDs.

Threshold decision reports count detected, missed, false-alarm and correctly negative events, plus warning lead-time distributions. Events already above a threshold at their first observed input receive no advance-warning credit and are reported separately. Onset is the first observed withheld crossing, **not a proven continuous physical onset**. Sampling gaps and onset annotation uncertainty still require domain review. Missing/OOD forecasts remain unavailable, count against event coverage and can count as missed hazards; they never become zero depth or a safe classification.

Approval now additionally requires a separately reviewed decision policy, sufficient calibration/test and positive/negative events, required reviewed storm-intensity strata, baseline gain at every horizon, positive whole-event gain bounds, acceptable misses/false alarms/lead time, interval width and withheld event coverage. The policy must match the station's commissioned thresholds and cannot understate its measurement uncertainty. The default values are engineering starting points, **not agreed LGU tradeoffs**. Do not change `status` to `reviewed` without retaining genuine independent evidence. Numeric gates supplement, rather than replace, source, licence, calibration and independent scientific review.

Intervals assume sufficiently comparable independent events. Distribution shift, changing land use, sensor faults and unsupported seasons can invalidate coverage. A rectangular training-feature range is an intentionally limited OOD check; being inside it is not proof of statistical similarity. There is no automatic retraining, threshold adjustment, model promotion or historical alert replay.

## Runtime fallback, drift and display

The adapter rejects depth/rate features outside its training-only range. Each publisher tick stores a station/binding input gate in the existing shared state table; failed or expired gates withhold an older product even if its original TTL has not elapsed. Generic viewer-cache eviction cannot remove fresh forecast gates. `FORECAST_INPUT_OUT_OF_DOMAIN` and `FORECAST_INPUT_UNAVAILABLE` distinguish those faults in operator diagnostics. Worker heartbeats now include the forecast worker. A successful later tick may restore availability under the same reviewed model; confirmed scientific regression requires disabling the binding or revoking approval, with actor/reason/version recorded.

Published products include interval bounds and method, policy hash, nominal coverage, actual withheld event coverage and event counts. Both clients reject incomplete/reversed intervals. Operational point values are approximate and rounded to a resolution no finer than the reviewed measurement uncertainty (and at least 1 cm). Bounds round outward for display. Private assumed-basin depth projections use whole centimeters and retain experiment labels; rounding does not validate the basin. Raw artifact/report values remain available for reproducible calculations. Experimental rainfall evaluation shows each horizon and dynamically discloses a first-hour persistence advantage when present; pooled scores never become flood accuracy.

The offline drift command accepts a bounded timestamped feature window and reports insufficient data, feature-domain stability or a rollback-required signal. Its provisional trigger is more than 10% OOD among at least 30 observations. Runtime rejects each OOD input immediately. This range monitor is **not residual/concept-drift validation**; delayed physical outcomes, representative seasons and the chosen monitoring cadence remain deployment responsibilities. Use the retained event-evaluation workflow for labeled performance review and revoke/disable a failing model. Never widen the domain or prolong expiry to silence a fault.

## Reproduction and release workflow

See [RUNBOOK.md](RUNBOOK.md) for offline evaluation, profile commands, clean-source rehearsal, artifact packaging and rollback. The production API uses database-held reviewed JSON models and requires no pandas, scikit-learn, private dataset or development hybrid endpoint. Optional hybrid dependencies have their own container target. An optional forecast-artifact target accepts an explicit independently approved registry export, retained licence-review evidence and a manifest SHA-256 supplied through the protected release record. It checks immutable model identity and hashes; it neither proves legal permission nor activates that model in another database.

Core, offline ML and hybrid integration jobs install explicit dependency sets under a common version-constraints file. A test-assignment check prevents new test files from silently escaping those profiles. Web checks run through `npm test`; a pinned Playwright workflow uses a production Next server and loopback synthetic API for zero/interval, history withdrawal, outage and staff-access behavior. CI installs its Chromium explicitly. Python/npm vulnerability jobs fail on findings. Forecast contract drift checks the actual OpenAPI exports used by TypeScript and Dart; Flutter runs the same generated corpus. Container builds and Linux hosted jobs are separate from Windows local verification.

Most preceding audit implementation is still untracked in this working tree. The clean-source tool includes allowlisted new source files to expose integration gaps without staging anything. A hosted checkout will only contain the final committed scope. Nothing was staged, committed, pushed or publicly deployed as part of this work.

The [NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework) informs this separation of intended use, measurement, monitoring and governance. It is a voluntary risk-management framework, not a certification or evidence that AGAPAY is field-ready.
